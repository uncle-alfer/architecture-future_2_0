# Домены и потоки данных Future 2.0

Те же обозначения сценариев:
- S1 - быстрая подготовка отчётности;
- S2 - независимое развитие финтех-направления;
- S3 - независимое развитие ИИ-направления;
- S4 - масштабирование для новых бизнесов и партнёров;
- S5 - безопасность и соответствие регуляторным требованиям.


## 1. Выделенные домены

### 1.1. Домен «Клиника»

Ответственность:
- операционная работа клиник: приёмы, диагнозы, процедуры, назначения;
- работа операторов и врачей с операционными медицинскими системами;
- использование медицинского оборудования в клиниках.

Основные системы домена:
- операционные медицинские системы **ClinicCore**;
- клиентский интерфейс оператора (UI), которым пользуются сотрудники клиник;
- часть внутренних сервисов управления клиниками (расписание, очереди, маршрутизация пациентов).

Данные домена:
- операционные медицинские события (приём, диагноз, назначение, процедура);
- статусы пациентов и нагрузки (очереди, занятость врачей и оборудования);
- ограниченный набор клинико-операционных атрибутов, разрешённых к аналитике
  (обезличенные и агрегированные данные без включения полных медицинских карт и сырых исследований).

Продукты данных домена:
- обезличенные наборы для анализа качества лечения и загрузки клиник (для S1, S3);
- агрегаты по объёмам услуг, очередям, SLA и т.д. для витрины данных (для S1).


### 1.2. Домен «Финтех»

Ответственность:
- финансовые продукты и банковские сервисы для клиентов Future 2.0;
- счета, платежи, кредиты, кредитные истории и рисковые профили;
- интеграция с внешними платёжными системами.

Основные системы домена:
- финтех-сервисы **FintechCore** (Golang/Java);
- часть внутренних финансовых сервисов (биллинг, платежи).

Данные домена:
- финансовая история клиентов;
- продукты и тарифы, кредитные заявки и решения;
- транзакции, платежи, задолженности, просрочки.

Продукты данных домена:
- витрины для отчётности по выручке, портфелю кредитов и рискам (S1, S2);
- наборы признаков (features) для скоринговых моделей и antifraud (S2, S3);
- агрегаты для партнёров (например, финпрофиль по сегментам без персональных данных).


### 1.3. Домен «Медицинский ИИ»

Ответственность:
- разработка и эксплуатация ИИ-сервисов по медицинским данным;
- обучение и валидация моделей, предоставление рекомендаций и скорингов.

Основные системы домена:
- операционные ИИ-сервисы **AIServices** (Python);
- окружение для обучения моделей и экспериментов.

Данные домена:
- обезличенные медицинские датасеты и фичи из доменов «Клиника», «Партнёры: фармацевтика» и «Партнёры: мед. оборудование»;
- результаты моделей: вероятности диагнозов, рекомендации по лечению, прогнозы рисков.

Продукты данных домена:
- ИИ-модели и сервисы скоринга (S3);
- витрины фичей и предсказаний, доступные через Платформу данных другим доменам (S2, S3, S4).


### 1.4. Домен «Партнёры: фармацевтика»

Ответственность:
- интеграция с фармацевтическими компаниями;
- обмен данными о лекарствах, поставках, продажах и, при необходимости, результатах клинических исследований.

Основные системы домена:
- интеграционные адаптеры к системам фармпартнёров;
- внутренние сервисы взаимодействия и контрактного учёта.

Данные домена:
- каталоги препаратов, регистрационные данные, инструкции;
- данные по поставкам и остаткам;
- агрегированные данные о продажах и назначениях (в обезличенном виде).

Продукты данных домена:
- витрины для анализа эффективности препаратов (S4);
- данные для совместных исследований с ИИ-доменом (S3, S4).


### 1.5. Домен «Партнёры: мед. оборудование»

Ответственность:
- интеграция с производителями и поставщиками медицинского оборудования и устройств;
- сбор телеметрии и статусов оборудования.

Основные системы домена:
- адаптеры к системам производителей;
- сервисы сбора телеметрии и логов устройств.

Данные домена:
- техническая телеметрия оборудования;
- статусы работоспособности и события ошибок;
- информация о конфигурации и обновлениях.

Продукты данных домена:
- витрины для анализа загрузки оборудования, времени простоя и надёжности (S1, S4);
- датасеты для предиктивного обслуживания совместно с доменом «Медицинский ИИ» (S3, S4).


### 1.6. Домен «Внутренние операции»

Ответственность:
- корпоративные функции, не относящиеся напрямую к медицине или финтеху:
  персонал, инвентаризация, финансовая отчётность и т.п.

Основные системы домена:
- системы управления персоналом;
- системы учёта инвентаря и основных средств;
- системы управленческого учёта.

Данные домена:
- данные по персоналу клиник и офисов;
- данные по инвентаризации и затратам;
- агрегированная финансовая отчётность.

Продукты данных домена:
- витрины для управленческой отчётности и планирования (S1);
- данные для анализа эффективности работы клиник и подразделений (S1, S4).


### 1.7. Домен «Платформа данных»

Ответственность:
- единая самообслуживаемая инфраструктура данных для всех доменов;
- реализация архитектуры Data Lakehouse и подхода Data Mesh.

Основные компоненты (соответствуют контейнерам из Task1):
- сервисы загрузки данных (Ingestion) - batch/stream загрузка из DWH, операционки и партнёров;
- стриминговая платформа (Streaming) для событийных данных;
- **Data Lakehouse** - хранение сырых и подготовленных данных по доменам;
- доменные витрины данных (DomainMarts) для клиники, финтеха, ИИ и партнёров;
- BI / портал самообслуживания (SelfService);
- API/сервисы доступа к данным (DataAPI) - REST/GraphQL для доменов и внешних партнёров;
- каталог и управление данными (Catalog) - метаданные и lineage;
- сервис управления доступом и политиками (Security) - RBAC/ABAC, маскирование, аудит.

DWH:
- **Legacy DWH (SQL Server 2008)** рассматривается как источник исторических данных;
- новая бизнес-логика **не добавляется в DWH**, а реализуется в доменных витринах и сервисах Платформы.


### 1.8. Домен «Безопасность и управление данными»

Ответственность:
- единые политики безопасности, качества данных и комплаенса;
- федеративное управление данными для всех доменов.

Основные элементы:
- единые политики доступа к медицинским и финансовым данным;
- стандарты схем, API, форматов и контрактов данных;
- мониторинг и аудит использования данных.

Продукты домена:
- набор политик и темплейтов для всех доменов;
- отчёты по доступам, нарушениям и качеству данных (S5).


## 2. Потоки данных между доменами и поддержка сценариев

На DFD (`future2.0-domains-dfd.drawio.xml`) потоки данных между доменами
обозначены стрелками, рядом с ними указаны сценарии S1–S5. Ниже кратко
показано, какие домены и типы данных участвуют в каждом сценарии.

### S1. Быстрая подготовка отчётности

- Домены «Клиника», «Финтех», «Внутренние операции», система «Legacy DWH» -> домен «Платформа данных»  
  Операционные и исторические данные (медицинские события, финансы, внутренние показатели).
- Домен «Платформа данных» -> сервис «BI / Портал самообслуживания»  
  Доменные витрины, на основе которых строятся управленческие и операционные отчёты.

### S2. Интеграция новых финтех-сервисов

- Домен «Финтех» ↔ домен «Платформа данных»
  Транзакции, статусы продуктов, скоринговые и платёжные данные.
- Домен «Платформа данных» -> сервис «BI / Портал» и домены «Клиника» / «Внутренние операции»  
  Общие витрины и API, использующие данные финтех-домена для расчётов и аналитики.

### S3. Использование ИИ для анализа медицинских данных

- Домены «Клиника» и партнёрские домены («Партнёры: фармацевтика», «Партнёры: мед. оборудование») -> домен «Платформа данных»  
  Обезличенные клинические события, результаты исследований, данные устройств.
- Домен «Платформа данных» -> домен «Медицинский ИИ»  
  Подготовленные фичи и обучающие выборки.
- Домен «Медицинский ИИ» -> домен «Платформа данных» -> домены «Клиника», «Финтех», сервис «BI / Портал»  
  Риски, прогнозы, рекомендации для встраивания в процессы и отчётность.

### S4. Подключение партнёров (фармацевтика, электроника)

- Домены «Партнёры: фармацевтика» и «Партнёры: мед. оборудование» ↔ домен «Платформа данных»  
  Продажи и движение препаратов, телеметрия оборудования, результаты исследований.
- Домен «Платформа данных» -> домен «Медицинский ИИ» и сервис «BI / Портал»  
  Обогащённые витрины и модели, учитывающие данные партнёров.

### S5. Безопасность и комплаенс

- Домен «Безопасность и управление данными» -> домен «Платформа данных»  
  Политики доступа, правила маскирования, требования аудита.
- Домен «Платформа данных» -> все домены и сервис «BI / Портал»  
  Применение политик к витринам, API и отчётам.
- Домен «Платформа данных» -> домен «Безопасность и управление данными»  
  Логи доступа и действий пользователей для проверки соответствия требованиям.


## 3. Обоснование разделения на домены и эффекты для бизнеса

1. Соответствие DDD и Data Mesh  
   - Домены соответствуют ключевым областям бизнеса: клиника, финтех, ИИ и партнёры.
   - Каждому домену можно назначить ответственную команду с полным циклом
     владения своими продуктами данных.
   - Платформа данных - единая инфраструктура и self-service-слой,
     который поддерживает доменные команды, но не отбирает у них контроль.

2. Снижение зависимости от монолитного DWH  
   - Legacy DWH становится одним из источников данных, а не единственной
     точкой бизнес-логики.
   - Новая логика реализуется в доменных витринах и сервисах Платформы данных.
   - Это прямой ответ на проблему «бутылочного горлышка» DWH и долгой
     отчётности.

3. Ускорение вывода продуктов  
   - Домены могут развивать свои витрины и API независимо, если соблюдают
     общие стандарты и политики.
   - Время на изменения сокращается: меньше согласований вокруг единой
     схемы DWH, больше автономии.

4. Масштабирование для новых партнёров (S4)  
   - Партнёрские домены подключаются как отдельные области с собственными
     контрактами данных.
   - Платформа данных обеспечивает техническую интеграцию и общие стандарты,
     не требуя переписывать существующие доменные решения.

5. Безопасность и комплаенс (S5)  
   - Выделение домена «Безопасность и управление данными» и его тесная
     интеграция с Платформой позволяют централизованно реализовать
     маскирование, RBAC/ABAC и аудит.
   - Это снижает риск нарушить регуляторные требования при подключении
     новых доменов и партнёров.

6. Соответствие требованиям витрины данных  
   - В витрину и доменные витрины не попадают сырые медицинские карты и
     результаты исследований - только обогащённые и обезличенные данные.
   - Это совмещает требования к аналитике и к защите персональных данных.
